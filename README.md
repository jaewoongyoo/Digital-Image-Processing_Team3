# Hand Beat — OpenCV 기반 비접촉식 리듬게임

## 실행 가능한 초안

Python 3.11/3.12에서 저장소 루트 기준으로 실행한다.

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python main.py --keyboard
# 웹캠 모드
.\.venv\Scripts\python main.py
# 로직 테스트 (외부 패키지 불필요)
.\.venv\Scripts\python -m unittest discover -s tests -v
```

- `SPACE`: 3초 카운트다운 후 시작, `R`: 초기화, `ESC`: 종료.
- 키보드 입력은 별도의 작은 **Keyboard input** 창에 포커스를 둔 상태에서 `D/F/J/K`를 사용한다. HOLD는 키를 끝까지 누른다. 게임 화면에서도 시작·초기화·종료 키를 사용할 수 있다.
- 웹캠 모드는 초록색 마커가 기본값이다. `HSV settings` 창에서 색상 범위를 조절한다. 좌측 마스크는 HSV 원본, 우측은 모폴로지 적용 결과다.
- 반전된 640×480 화면에서 손을 y=260 위로 올려 준비한 뒤 y=340 아래로 내려친다. HOLD는 해당 레인의 y=320~479에 유지한다. 누락/이탈 허용시간은 0.2초다.
- 기본 20초 테스트 음원은 첫 실행 때 직접 합성한 120 BPM 클릭 트랙으로 생성한다. 외부 음원 다운로드 없이 TAP/HOLD를 시험할 수 있다.
- 사용자 음원은 JSON의 `audio`를 수정한다. 경로는 **차트 파일이 있는 폴더 기준**이다. 예: `../assets/test_music.mp3`. `--chart 경로`로 다른 차트를 지정한다.
- `--camera 1`로 카메라 번호를 변경한다. `--audio-offset-ms 100`은 차트 시계를 음원 재생 호출보다 100ms 늦춘다. 장시간 오디오 드리프트 자동 보정은 아직 없다.
- 초안의 HOLD 배점은 완료 시 시작 판정 점수(300/100) + 보너스 300점이며 중단 시 0점이다. 노트당 판정·콤보는 한 번만 반영한다.

현재 초안은 영상처리, TAP/HOLD, 수동 JSON 채보, 음원 재생, 점수·콤보, 결과·재시작을 포함한다. 실제 웹캠 인식률, 오디오 지연, FPS 목표 달성은 장치에서 검증해야 한다. 아래는 원본 기획서다.

## 1. 프로젝트 개요

### 1.1. 기획 배경

일반적인 리듬게임은 키보드·마우스·터치스크린을 입력 장치로 사용한다. Hand Beat는 **웹캠 영상에서 손의 위치와 동작을 검출**하고, 이를 리듬게임 입력으로 변환하는 프로젝트다. HSV 색상 분할, 필터링, 모폴로지 연산, 윤곽선 검출 등 영상처리 알고리즘을 실제 인터랙션에 활용한다.

### 1.2. 핵심 목표

1. OpenCV로 손의 위치를 실시간 추적한다.
2. 손의 **내려치기(TAP)** 동작을 순간 입력으로 판정한다.
3. 손을 내린 뒤 해당 레인에 **계속 유지(HOLD)** 하는 동작을 롱 노트 입력으로 판정한다.
4. 로컬 음원과 사전에 작성한 노트 데이터를 동기화하여 한 곡을 처음부터 끝까지 플레이한다.
5. 영상처리 적용 전후의 인식 안정성과 게임 반응성을 측정한다.

### 1.3. 1차 범위와 제외 범위

| 구분 | 포함 | 이번 단계에서 제외 또는 후순위 |
| --- | --- | --- |
| 음악 | 다운로드한 MP3/WAV 1곡 로컬 재생 | 유튜브·스트리밍 연동, 자동 음원 검색 |
| 노트 | 일반 노트(TAP), 롱 노트(HOLD) | 슬라이드, 폭탄, 동시 타격 |
| 조작 | 웹캠 + HSV 색상 마커 추적 | AI 기반 정밀 손가락·손바닥 자세 인식 |
| 게임 | 기본 4레인, 점수·콤보·결과 화면 | 랭킹 서버, 온라인 멀티플레이 |
| 패턴 | JSON 수동 채보 | 실시간 음악 비트 자동 분석 |
| 메뉴 | 키보드로 시작·종료·재시작 | 손동작 메뉴, 화려한 외부 GUI |

**완료 정의(MVP):** 팀원이 웹캠 앞에서 준비 동작을 하고, 테스트 음원 1곡을 TAP/HOLD 노트로 플레이한 뒤 최종 점수와 결과 화면을 확인할 수 있다.

## 2. 사용자 경험 및 플레이 흐름

```text
프로그램 실행
    ↓
웹캠 연결 및 HSV 검출 상태 확인
    ↓
손 위치/판정선 보정(필요 시)
    ↓
게임 시작 → 3초 카운트다운
    ↓
테스트 음원 재생 + 노트 하강
    ↓
손동작 인식 → TAP / HOLD 판정
    ↓
점수·콤보·이펙트 갱신
    ↓
곡 종료 → 결과 화면
    ↓
재시작 / 종료
```

### 2.1. 기본 화면 구성

- **상단:** 현재 점수, 콤보, 남은 시간 또는 곡 진행도
- **중앙:** 4개 레인과 아래로 내려오는 노트
- **하단:** 노트 판정선, 손 커서(검출 중심점), `PERFECT / GOOD / MISS` 피드백
- **설정/디버그 화면:** 웹캠 원본, HSV 마스크, 필터링 결과, FPS, 손 좌표
- **결과 화면:** 총점, 최고 콤보, TAP/HOLD 성공률, 판정별 개수

### 2.2. 카메라 배치와 초기 가정

- **기준 구현:** 노트북/USB 웹캠을 **사용자 정면**에 두고, 손바닥에 부착한 **식별하기 쉬운 단색 스티커** 또는 단색 장갑을 추적한다.
- 좌우 반전된 화면에서 손을 보며 조작한다. 레인의 X좌표는 웹캠 영상 가로폭을 기준으로 4등분한다.
- TAP은 손을 준비 영역에서 **아래 방향으로 내리쳐 판정선 통과**하는 동작이다.
- HOLD는 같은 방식으로 시작한 뒤 **손바닥의 마커가 카메라에 보이도록 해당 레인의 홀드 영역에 지속적으로 유지**하는 동작이다.
- **중요:** HSV 기반 추적만으로는 실제로 손바닥이 펴졌는지 판단할 수 없다. 1차 버전에서 HOLD의 조건은 *손바닥 모양 인식*이 아니라 *마커 위치 유지*다. 손바닥 개폐 감지는 후속 확장이다.
- 카메라 각도와 인식 환경에 따라 판정선 높이, 영역 넓이, 색상 범위를 조정하도록 설계한다.

## 3. 노트 및 입력 규칙

### 3.1. 일반 노트 — TAP

**플레이 방식:** 노트가 판정선에 도착할 때 해당 레인에서 손을 아래로 내리친다.

1. 손 마커가 판정선 위의 준비 영역에 들어오면 `READY` 상태가 된다.
2. 손 중심이 판정선을 **위→아래로 통과**하고 하강 이동량/속도 조건을 만족하면 `HIT` 이벤트를 1회 발생시킨다.
3. 이벤트 발생 시 해당 레인의 가장 가까운 미처리 노트와 목표 시각을 비교한다.
4. 판정 후에는 손을 다시 준비 영역까지 올려야 다음 타격이 가능하다.

> 단순히 판정선 위에 손을 고정해 놓는 경우는 TAP 성공으로 처리하지 않는다.

### 3.2. 롱 노트 — HOLD

**플레이 방식:** 롱 노트의 **시작 지점**에서 손을 내려치고, **끝나는 시점까지 같은 레인의 홀드 영역에 손을 계속 유지**한다.

1. **HOLD_START:** 롱 노트의 시작 시각 부근에서 TAP과 동일한 내려치기로 시작한다.
2. **HOLDING:** 손 마커가 지정된 레인의 홀드 ROI(관심 영역)에 계속 존재하는지 확인한다.
3. **HOLD_COMPLETE:** 끝 시각까지 유지하면 성공, 중간에 오래 벗어나면 실패한다.
4. 인식이 순간적으로 끊기는 경우를 대비하여 **약 0.2초 이내의 짧은 검출 누락은 임시 허용**한다(테스트 후 조정).
5. HOLD 중에는 같은 손에서 TAP 이벤트가 연달아 발생하지 않도록 입력 상태를 잠근다.

**초기 채보 제한:** 한 손으로 개발·시연하는 1차 버전에서는 HOLD가 진행되는 동안 다른 레인에 TAP을 배치하지 않는다. 동시 입력은 추후 양손 인식을 구현한 뒤 확장한다.

### 3.3. 타이밍 판정(초기 기준)

| 판정 | 목표 시각과 타격 이벤트 시각의 차이 | 예시 점수 |
| --- | --- | ---: |
| PERFECT | 절댓값 0.10초 이하 | 300 |
| GOOD | 절댓값 0.20초 이하 | 100 |
| MISS | 0.20초 초과 또는 타격 누락 | 0 |

- 위 수치는 **초기 튜닝 값**이며 웹캠·오디오 지연 측정 후 보정한다.
- 노트 하나는 한 번만 판정한다.
- 정해진 판정 시간을 초과한 미처리 노트는 자동 `MISS` 처리한다.
- HOLD 점수는 **시작 판정 + 유지 성공 여부**를 기준으로 설계하며, 구체적인 배점은 3주차 통합 시 확정한다. 예: 시작 PERFECT/GOOD 점수 + 완료 보너스.
- `MISS` 발생 시 콤보를 0으로 초기화한다. HOLD 중단 시에도 실패 처리가 필요하다.

## 4. 영상처리 파이프라인

```text
웹캠 프레임 수집
   → 좌우 반전 및 크기 조정
   → Gaussian Blur(원본 프레임 잡음 완화)
   → BGR → HSV 변환
   → inRange 색상 마스크 생성
   → Morphological Opening / Closing
   → Contour 검출 및 최소 면적 필터링
   → Moments로 마커 중심 좌표(x, y) 계산
   → 최근 좌표 기반 이동 방향/속도 분석
   → TAP 이벤트 또는 HOLD 지속 상태
   → 게임 판정 로직에 전달
```

| 영상처리 기술 | 적용 목적 | 주요 함수 |
| --- | --- | --- |
| HSV 색상 분할 | 지정 색상 스티커·장갑 검출 | `cv2.cvtColor`, `cv2.inRange` |
| Gaussian Blur | 색상 분할 전에 노이즈 완화 | `cv2.GaussianBlur` |
| Median Blur(선택) | 소금·후추 형태 잡음 감소 | `cv2.medianBlur` |
| Morphological Opening | 마스크 외부의 작은 점 제거 | `cv2.morphologyEx` |
| Morphological Closing | 마스크 내부의 작은 구멍 메우기 | `cv2.morphologyEx` |
| Contour Detection | 색상 마커 후보 영역 추출 | `cv2.findContours` |
| Image Moments | 검출 영역의 중심 좌표 계산 | `cv2.moments` |
| ROI(관심 영역) | 레인 구분 및 HOLD 유지 판별 | NumPy 슬라이싱/좌표 검사 |
| 프레임 간 좌표 분석 | 하강 타격·상승 복귀 인식 | 좌표 차분, 시간 차분 |
| Optical Flow(선택) | 향후 슬라이드 동작 분석 | `cv2.calcOpticalFlowPyrLK` |

### 4.1. 손 인식 안정화 규칙

- HSV 범위는 환경별로 조절 가능하도록 상수 또는 Trackbar로 관리한다.
- 가장 큰 Contour만 선택하되, **최소 영역 면적** 미달 시 손 미검출로 처리한다.
- 중심 좌표가 순간적으로 튀는 현상은 이동 평균 등으로 완화할 수 있다.
- 위치 스무딩은 과도하면 입력 지연이 생기므로 타격 반응성도 함께 측정한다.
- 배경에 같은 색상의 물체가 있으면 오인식할 수 있으므로 테스트 배경과 조명을 일정하게 유지한다.

### 4.2. TAP 상태 머신

```text
READY(손이 판정선 위에 있음)
  └─ 충분한 하강 + 판정선 교차 → HIT 1회 → LOCKED
LOCKED
  └─ 손이 재준비선 위로 올라옴 → READY
```

- **재준비선(`reset_y`)**을 **판정선(`hit_y`)보다 위**에 두는 히스테리시스 방식으로 떨림에 의한 연속 입력을 줄인다.
- 필터링된 좌표만이 아니라 타임스탬프를 사용해 `dy / dt` 속도를 확인한다.
- 추적이 끊기면 임의 타격을 발생시키지 않는다.

### 4.3. HOLD 상태 머신

```text
WAITING → (정확한 시작 타격) → HOLDING
HOLDING → (끝 시각까지 ROI 유지) → COMPLETED
HOLDING → (ROI 이탈/검출 누락 허용시간 초과) → FAILED
```

### 7.2. 팀 간 공유 데이터 규격(1주차에 확정)

**손 검출 결과**

```python
{
    "detected": True,
    "x": 320,             # 좌우 반전된 카메라 화면의 픽셀 좌표
    "y": 280,
    "area": 2400,         # 검출된 마커의 Contour 면적
    "timestamp": 1234.56  # time.monotonic() 기준
}
```

**타격 이벤트**

```python
{
    "type": "tap",       # 일반 시작 타격; 롱노트 시작에도 사용
    "lane": 2,           # 0, 1, 2, 3 중 하나
    "time": 5.24         # 음악 시작 기준 보정된 경과시간(초)
}
```

**노트 데이터**

```json
{
  "title": "Test Music",
  "audio": "assets/test_music.mp3",
  "notes": [
    {"id": 1, "type": "tap", "lane": 0, "time": 2.0},
    {"id": 2, "type": "hold", "lane": 1, "time": 4.0, "duration": 2.0},
    {"id": 3, "type": "tap", "lane": 3, "time": 7.0}
  ]
}
```

- 레인은 **0부터 시작**하며 오른쪽으로 갈수록 숫자가 증가한다.
- `time`: 노트를 *쳐야 하는* 음악 시작 기준 시각(초). 노트 생성 시각이 아니다.
- `duration`: HOLD 지속 시간(초). 종료 시각 = `time + duration`.
- 노트는 한 번 판정되면 재판정되지 않도록 상태(`pending`, `holding`, `hit`, `miss`, `complete`)를 관리한다.
- HIT 이벤트의 타임스탬프는 게임에서 사용하는 **동일한 음악 경과시간 기준**으로 변환한다.

### 7.3. 타이밍 동기화 원칙

1. 게임 시작 시 `time.monotonic()` 기준 시각을 기록한다.
2. 노트 Y좌표는 프레임별 이동량 누적이 아니라 **현재 게임 시간과 목표 타격 시각**으로 계산한다.
3. 음악 재생 함수 호출과 실제 소리 출력 사이의 지연을 고려해 `audio_offset_ms` 같은 보정 파라미터를 둔다.
4. 성능 저하로 FPS가 변해도 노트의 목표 타격 시각은 변경하지 않는다.
5. 단순한 오디오 시계와 게임 시계가 장시간 어긋나는지 곡 재생 테스트에서 확인한다.

**노트 위치 계산식(예시)**

```python
note_y = hit_line_y - speed_px_per_sec * (note_time - song_time)
```

### 10.2. 성능·영상처리 실험

| 평가 항목 | 측정 방법 | 초기 목표(조정 가능) |
| --- | --- | --- |
| 처리 FPS | 게임 구동 중 평균 FPS 측정 | 20FPS 이상 |
| 타격 검출 성공률 | 정해진 TAP 동작 100회 중 이벤트 검출 비율 | 90% 이상 |
| 오입력 | 손을 가만히 둔 테스트 구간에서 발생한 이벤트 수 | 가능한 0에 가깝게 |
| HOLD 성공률 | 1~3초 HOLD 동작 반복 수행 | 안정적인 유지·완료 판정 |

> 수치는 **보장된 성능이 아닌 프로젝트의 목표값**이다. 조건(조명, 배경, 카메라 거리, 사용자)을 기록하고 같은 조건에서 반복 실험한다.

### 10.3. 발표 시연 권장 순서

1. 원본 카메라 → HSV 마스크 → 모폴로지 처리 화면을 비교한다.
2. 마커 중심 좌표 및 레인 인식 결과를 보여준다.
3. TAP 노트 3~5개를 직접 내려쳐 판정한다.
4. HOLD 노트 1개를 유지하여 완료한다.
5. 짧은 테스트 곡을 플레이하고 결과 화면을 확인한다.
6. 실험 표로 필터 적용 전후의 차이를 설명한다.

## 13. 현재 결정 사항과 미결정 사항

### 확정

- 4명, 6주 개발
- OpenCV 중심의 Python 프로젝트
- 초기 테스트 음악은 다운로드한 로컬 파일 **1곡**

- **4주차까지 플레이 가능한 MVP 달성**

### 개발 착수 시 결정할 사항

- 사용 웹캠 종류 및 실제 배치(정면 카메라를 기본안으로 채택)

## 14. 최종 성공 기준

프로젝트는 아래 조건을 모두 충족하면 1차 완료로 본다.

- [ ] 웹캠에서 손 마커의 위치를 안정적으로 검출한다.
- [ ] HSV, Blur, Morphology, Contour가 실제 입력 인식에 적용된다.
- [ ] TAP은 내려치기 때만 1회 입력되고, 손 고정만으로 자동 처리되지 않는다.
- [ ] HOLD는 시작 타격 이후 레인 위치 유지 여부에 따라 성공/실패한다.
- [ ] JSON 노트 데이터와 로컬 음원 1곡이 정상 재생·동기화된다.
- [ ] PERFECT/GOOD/MISS, 점수, 콤보, 결과 화면이 동작한다.
- [ ] 프로그램 재시작과 주요 예외 처리에 문제가 없다.
- [ ] 영상처리 적용 전후 비교 실험과 발표용 시연을 준비한다.
