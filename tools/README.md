# Hand Beat 자동 채보

WAV·MP3에서 타격 시점을 찾아 기존 Hand Beat JSON 채보를 생성합니다. 프로젝트 루트에서 실행합니다.

```powershell
python -m pip install -r requirements.txt
python tools/auto_chart.py "assets/Quatre sur le sol.mp3" -o charts/quatre_custom.json --difficulty normal --diagnostics tools/diagnostics/quatre_custom.json
python main.py --keyboard --chart charts/quatre_custom.json
```

| 인자 | 동작 |
| --- | --- |
| `audio` | 분석할 음원 경로 |
| `-o`, `--output` | 필수. 출력 JSON 경로 |
| `--difficulty easy\|normal\|hard` | 기본값은 `normal` |
| `--min-gap` | 난이도의 최소 노트 간격을 초 단위로 재지정 |
| `--lead-in` | 첫 노트 허용 시각. 기본 1초 |
| `--enable-hold` | 안정적으로 지속되는 소리의 TAP을 선택적으로 HOLD로 변환 |
| `--diagnostics` | 분석 정보와 파형을 별도 JSON에 저장 |

채보와 진단 파일은 새 파일명으로 생성합니다. 같은 이름의 파일이 있으면 오류를 표시합니다. 음원 경로는 출력 파일 기준 상대 경로이며, Windows에서 드라이브가 다르면 절대 경로를 사용합니다.

| 난이도 | 기본 최소 간격 | 목표 노트/분 | 타격 선택 |
| --- | ---: | ---: | --- |
| Easy | 0.360초 | 75 | 강한 타격과 주요 박자 |
| Normal | 0.250초 | 141 | 주요 리듬과 일부 세부 타격 |
| Hard | 0.135초 | 228 | 더 약한 타격과 빠른 연타 |

목표 밀도는 상한을 정하는 기준입니다. 약한 구간이나 타격 후보가 적은 곡은 목표보다 적게 나오며, 원래 일정한 클릭만 있는 데모에서는 Normal과 Hard가 같은 노트 수를 가질 수 있습니다.

## 분석 방식

1. **타격 감지** — 네 주파수 대역에서 양의 스펙트럼 변화를 따로 측정합니다. 주변 프레임의 평균과 곡 전체 대역 수준으로 임계값을 조절하고, 중복 피크와 에너지가 크게 감소하는 지속음의 끝을 걸러냅니다. 고역 단독 변화는 낮게 가중하고 피크는 포물선 보간으로 정밀화합니다.
2. **템포 평가** — 자기상관의 여러 피크와 절반·두 배 후보를 비교합니다. 반복성, 박자 점유율, 4분·8분·16분 정렬도와 스윙 패턴을 점수화합니다. 곡 내부에서 템포 후보가 엇갈리거나 위상이 불안정하면 신뢰도를 낮춥니다. `bpm_confidence`는 0~1 휴리스틱 점수이며, 후보를 정하기 어려우면 `bpm`과 `beat_offset`은 `null`입니다.
3. **타이밍과 밀도** — 신뢰도가 0.55 이상이면 4분·8분·16분 위치와 비교해 각각 최대 16·14·10ms 이내의 타격만 정렬합니다. 그 밖의 타격은 감지 위치를 유지합니다. 근처 박에서 반복되는 타격에 가중치를 주고, 4초 단위 RMS와 타격 밀도를 평활화해 구간별 노트 예산을 조절합니다.
4. **레인과 HOLD** — 정규화한 주파수 반응과 비슷한 리듬 위치에서 사용한 레인을 우선합니다. 한 레인으로 과도하게 몰리거나 같은 레인이 네 번 이상 연속되는 배치를 제한합니다. HOLD 옵션은 약 0.7~2.5초 동안 RMS가 안정적이고 내부 타격이 적을 때만 선택하며, 다음 TAP까지 최소 100ms를 남깁니다. 기본 출력은 모든 난이도에서 TAP만 사용합니다.

기존 채보의 `id`, `type`, `lane`, `time`과 HOLD의 `duration`을 그대로 사용합니다. 노트 시각과 길이는 초 단위이며 레인 번호는 0~3입니다.

## 진단과 비교 결과

[Quatre 진단 JSON](diagnostics/auto_v3_quatre.json)의 `audio`와 `waveform`은 같은 음원의 경로와 약 50ms 단위 파형 최소·최대값입니다. `notes[].onset`과 `notes[].time`을 같은 시간축에 올리면 감지 위치와 출력 위치를 비교할 수 있습니다. `timing`에는 절대 오차의 평균, 중앙값, 95백분위, 최대값이 밀리초 단위로 들어갑니다. 그리드를 적용하지 않아도 BPM 후보가 남아 있으면 참고용 그리드 오차를 기록하며, 적용 여부는 `grid_used`로 구분합니다.

같은 원본 음원, 1초 리드인, 0.25초 최소 간격으로 기존 생성기와 새 Normal을 비교했습니다. 분석 시간은 디코딩을 제외한 3회 중앙값입니다.

미적용 곡의 소수점 차이는 밀리초 단위 반올림에서 생깁니다. RMS 수치는 약 5ms 구간으로 검출한 가장 가까운 에너지 상승점까지의 거리입니다. 박자의 음악적 적합성이나 실제 플레이 싱크를 직접 측정한 값은 아닙니다. 검증한 세 곡과 데모는 HOLD 옵션을 켜도 조건을 만족한 구간이 없었습니다. 합성 지속음에서는 HOLD 한 개가 생성됐고 다음 TAP과 겹치지 않았습니다.

단일 BPM을 추정하므로 변속 구간별 템포 맵을 만들지는 않습니다. 악기 분리 없이 혼합 음원의 주파수 반응을 사용하므로 주된 악기나 레인 배정의 음악적 의도는 플레이로 확인해야 합니다. 재생 환경의 타이밍 보정은 [싱크 보정 README](../README.sync.md)를 참고하세요.
